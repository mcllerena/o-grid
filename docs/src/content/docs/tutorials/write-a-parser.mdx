In this tutorial you will parse an ANAREDE `.pwf` case into an `infrasys` `System`
and inspect the typed components the parser creates. It expands on the runnable
[`examples/parser_script.py`](https://github.com/mcllerena/o-grid/blob/main/examples/parser_script.py).

## What you'll build

A short script that:

- configures the parser with an `AnaredeConfig`,
- runs the `AnaredeParser` plugin through a `PluginContext`, and
- queries the resulting `System` for buses, lines, and generators.

:::tip[Before you start]
- Run commands from the repository root.
- Install the workspace with `uv sync --all-groups`.
- Import model classes from `o_grid.models` and the parser from `o_grid`.
:::

## Step 1: Pick a case file

The repository ships several ANAREDE cases under `tests/data/pwf/`. This
tutorial uses the 33-node distribution feeder:

```text
tests/data/pwf/d_33nodes.pwf
```

## Step 2: Configure and run the parser

Create `tmp_parser_example.py` in the repository root:

```python
from pathlib import Path

from r2x_core import DataStore, PluginContext

from o_grid import AnaredeConfig, AnaredeParser

data_path = Path("tests/data/pwf/d_33nodes.pwf")

# 1. Describe the parse job.
config = AnaredeConfig(
    system_name="d_33nodes",
    pwf_path=str(data_path),
)

# 2. Give the plugin a context: its config plus a data store rooted at the case folder.
context = PluginContext(config=config, store=DataStore(path=data_path.parent))

# 3. Run the parser and take the populated infrasys System.
system = AnaredeParser.from_context(context).run().system

print(system.name)
```

The three moving parts are:

| Object | Role |
| --- | --- |
| `AnaredeConfig` | Declares *what* to parse — the case path and system name. Optional fields include `mapping_path` (override the column mapping) and `model_year`. |
| `PluginContext` | Binds the config to a `DataStore` so the plugin can resolve files. |
| `AnaredeParser` | The `r2x-core` plugin that reads the case and returns the `System`. |

## Step 3: Run the script

```bash
uv run python tmp_parser_example.py
```

The output is the system name:

```text
d_33nodes
```

## Step 4: Query the components

Every ANAREDE block becomes a typed component you can retrieve with
`system.get_components(...)`. Add the following to your script:

```python
from o_grid.models import ACBus, ACLine, Generator

buses = list(system.get_components(ACBus))
lines = list(system.get_components(ACLine))
generators = list(system.get_components(Generator))

print(f"buses: {len(buses)}")
print(f"lines: {len(lines)}")
print(f"generators: {len(generators)}")

first_bus = buses[0]
print(first_bus.name, first_bus.base_voltage, first_bus.bustype)
```

Because the components are typed [`pydantic`](https://docs.pydantic.dev/) models,
attributes such as `base_voltage` carry physical units (kV, MW, MVAr, p.u.) and
are validated when the parser builds them.

## Step 5: Override the column mapping (optional)

The parser reads column positions from
[`config/anarede_mapping.json`](https://github.com/mcllerena/o-grid/blob/main/src/o_grid/config/anarede_mapping.json).
To use a customized mapping, point `AnaredeConfig` at your own file:

```python
config = AnaredeConfig(
    system_name="d_33nodes",
    pwf_path="tests/data/pwf/d_33nodes.pwf",
    mapping_path="my_custom_mapping.json",
)
```

No parsing code changes — the mapping alone controls how each block's fields are
sliced and defaulted.
